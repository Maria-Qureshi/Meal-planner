## 🧭 Overview

Standard recipe search needs an exact dish name and matches keywords — it ignores semantic relationships and cannot relate *"scallions"* to *"chives"*. This project treats each recipe as a **"sentence"** and each ingredient as a **"word"**, learns ingredient embeddings, and recommends recipes by **embedding-similarity overlap** between what you have and what a recipe needs.

**Objectives:**

- Build an end-to-end pipeline: preprocessing → embedding training → recommendation → web UI
- Implement the core ML algorithm (skip-gram + negative sampling) **from scratch** in NumPy
- Score recipes by **semantic** ingredient similarity, not lexical overlap
- Provide a working demo on a sample dataset with a clear scaling path

## ⚙️ How It Works

1. **`preprocess.py`** — Cleans raw ingredient text (lowercasing, stripping punctuation/units, naive singularization) and loads the recipe dataset.

2. **`train_embeddings.py`** — The ML component. Trains ingredient embeddings using **Word2Vec's skip-gram architecture with negative sampling**, implemented from scratch in NumPy (no external ML library). Every ingredient in a recipe is treated as "context" for every other ingredient in that recipe, so ingredients that co-occur across many recipes (e.g. `soy sauce`, `ginger`, `rice`) end up close together in vector space. Run this once to produce `embeddings.npz`.

3. **`recommend.py`** — Given a main ingredient + other ingredients:
   - Filters the recipe dataset to ones containing the main ingredient
   - Scores each candidate recipe by embedding-similarity overlap between what the user has and what the recipe needs
   - Returns ranked results with a **missing ingredients** list per recipe

4. **`app.py`** + **`templates/index.html`** — A small Flask web app with a form for main ingredient + other ingredients, showing ranked results.

🔄 Swapping in the Real Dataset
Download the CSV from Kaggle (see Datasets) and place it in data/.

Update DATA_PATH in train_embeddings.py and recommend.py to point at the new file.

Check the ingredients column format. Food.com / RecipeNLG store ingredients as a stringified Python list — e.g. "['1 cup flour', '2 eggs']" — rather than a plain comma-separated string. Add a small adapter in preprocess.load_recipes() to convert that to the format parse_ingredient_list() expects (or update the parser directly).

Re-run train_embeddings.py. With a much bigger vocabulary and more co-occurrence data, expect training to take longer. If training time becomes an issue on your machine, consider reducing EPOCHS or capping the vocabulary to the N most frequent ingredients.

📈 Evaluation Plan
This is unsupervised representation learning + ranking, so classification/regression metrics do not apply directly. Appropriate analogues:

Component	Metric	Status
Embedding quality	Held-out ingredient recovery (top-k accuracy); loss curves	Planned
Ranking	Precision@k, Recall@k, MRR vs. TF-IDF baseline	Planned
Current validation: Per-epoch loss decreases monotonically on the sample data — confirming correct optimization of the SGNS objective.

⚠️ Limitations
Small corpus: 30 recipes is far too few for reliable embeddings.

Whole-recipe blur: whole-recipe context ignores dish structure (sauce vs. garnish).

Naive singularization: mishandles irregular plurals.

_best_substitute() is an unimplemented stub.

No quantitative metrics measured yet.

Data bias: recipe corpora over-represent certain cuisines; dietary constraints are not modeled.
